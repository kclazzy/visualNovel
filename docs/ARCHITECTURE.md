# Архитектура

## Модули

```
vn-core    чистая логика, без ввода-вывода
  model      форма данных истории (JSON), постоянные ID
  cond       условия: разбор текста, вычисление
  runtime    состояние игры и её продвижение
  view       что показать сейчас (одно для всех экранов)
  save       сохранения, версии, восстановление после обновлений
  validate   проверка целостности
  analysis   достижимость, концовки
  templates  шаблоны событий, копирование сцен и глав
  draft      черновик от ИИ → сцены
vn-store   файлы
  project    папка проекта: чтение, атомарная запись, резервные копии, автосохранение, ресурсы
  pack       .vnpak: сборка, чтение, слияние обновления
  export     игра для Windows, веб-версия, файл обновления, установка обновлений
  saves      сохранения игрока в каталоге данных пользователя
  demo       демо-проект «Свет маяка»
vn-view    отрисовка игры на egui + звук (rodio); общий для плеера и предпросмотра
vn-player  исполняемый файл игры
vn-studio  редактор
  app, left, timeline, props, stage, graph, extra, ai_panel   интерфейс
  ops        правки истории (чистые функции)
  history    отмена/повтор
  ai         запросы к ИИ
  update     обновление редактора с GitHub
  lanserve   раздача веб-версии телефону по Wi-Fi
player-web веб-плеер для телефона: runtime.js (движок), player.js (экран), sw.js (офлайн)
```

Зависимости идут в одну сторону: `vn-core ← vn-store ← vn-view ← vn-player, vn-studio`.
Редактор и игра независимы: игре нужен только `vn-player` и файл `.vnpak`.

## Данные

Проект на диске:

```
project.json                 название, версии, разрешение, главы, порядок сцен
story/scenes/<id>.json       по файлу на сцену: порча одного файла не губит проект
story/characters/…           персонажи, гардероб
story/variables/…            переменные
story/branches/…             положение узлов графа
assets/{backgrounds,characters,clothing,music,sounds,ui}/
saves/  backups/  builds/  changelog/  previews/
```

Все пути относительные; проект переносится копированием папки.
Запись — через временный файл и переименование. Удалённые файлы сцен уходят в `backups/trash`.

## Решения и их причины

**Позиция игрока — это ID сцены и ID события.** Номера строк и порядковые номера не используются,
поэтому автор может вставлять и переставлять события, а старые сохранения остаются верными.
При загрузке: событие найдено → продолжаем с него; сцена есть, события нет → начало сцены;
сцены нет → перенаправление (`redirects`) → запасная сцена → понятное сообщение о несовместимости.

**Сюжет — данные, а не код.** Движок не компилируется под историю; обновление — замена `.vnpak`.

**Один «вид» для всех экранов.** `Runtime::view()` возвращает готовое к показу: слои спрайтов,
текст с подставленными переменными, доступные варианты. Экраны только рисуют.

**Веб-плеер — отдельная реализация движка на JS, сверяемая трассой.** Собрать `vn-core` в WebAssembly
в среде разработки не удалось (нет цели `wasm32`), а непроверенное отдавать нельзя. Поэтому
`player-web/runtime.js` повторяет `runtime.rs` и `view.rs`, а тест `crates/vn-core/tests/conformance.rs`
записывает эталон «команды → вид» (`trace.json`), по которому `conformance.test.js` проверяет JS.
Любое изменение правил в Rust без того же изменения в JS ломает тест. Когда появится сборка wasm,
`runtime.js` заменяется тонкой обёрткой, остальное не меняется.

**Отрисовка — egui через OpenGL (glow), не wgpu.** В ТЗ wgpu назван предпочтительным. Выбран glow:
его можно запустить и проверить в среде разработки, он аппаратно ускорен и работает на старых
видеокартах. Переключение — одна возможность `eframe` в `Cargo.toml`, код отрисовки не меняется.

**Условия хранятся деревом, вводятся текстом.** Текст разбирается один раз — в редакторе;
движок получает проверенное дерево. Допустимы `и/или/не`, `and/or/not`, скобки, шесть сравнений.

**Отмена — снимки истории.** Истории невелики, сравнение и копия раз в кадр при вводе дешевле
и надёжнее журнала операций. Быстрые подряд идущие правки склеиваются в один шаг.

**ИИ не видит ID.** Модель возвращает черновик с собственными ключами сцен; ID назначает редактор.
Ответ проверяется на входе; в проект он попадает только после просмотра автором.

**Ключ API лежит вне проекта** — в настройках редактора, чтобы не уйти в игру или репозиторий.

**Обновление редактора не удаляет прежние файлы**, а переименовывает их в `*.old`: работающую
программу в Windows нельзя перезаписать, но можно переименовать; старые копии убираются при следующем запуске.

## Куда расти

Новое событие = вариант `EventKind` + ветка в `Stage::apply`/`Runtime` + форма в `props.rs` + то же в `runtime.js`
(трасса напомнит). Анимации и эффекты — новые поля `View`; инвентарь, достижения, отношения — переменные
и новые события; локализация — таблица строк рядом с текстом событий по их ID.

## Отступления от ТЗ

| ТЗ | Сделано | Почему |
|---|---|---|
| wgpu | glow (OpenGL) | проверяемость в среде разработки; см. выше |
| kira или rodio | rodio | достаточно для музыки, эффектов и плавной громкости |
| tokio, tracing, walkdir | не используются | потоки и `std` покрывают задачу; ошибки запуска игры пишутся в `errors.log` |
| папка игры `assets/` | ресурсы внутри `game_data/story.vnpak` | один файл проще обновлять |
| узлы «условие», «переменная» в графе | подписи на переходах | узлы графа — сцены; условия и переменные живут в событиях |
