# Журнал работ

Что делалось и зачем, по порядку. Принципы: сначала работает, потом правильно; форма данных
раньше логики; тест проверяет поведение глазами пользователя.

| № | Действие | Причина |
|---|---|---|
| 1 | Прочитано ТЗ целиком и примеры интерфейса | Определить объём и раскладку окна |
| 2 | Проверена среда: нет цели wasm32, нет Windows-цели, есть Mesa и xvfb | Понять, что можно проверить запуском |
| 3 | Модель данных `vn-core::model` с ID-типами | Сохранения и ссылки держатся на постоянных ID |
| 4 | Условия: разбор текста и вычисление, с тестами | Ввод автора — граница, где данные проверяются |
| 5 | Рантайм, вид, сохранения с восстановлением, проверка, анализ концовок, шаблоны, черновик ИИ | Вся логика без ввода-вывода, покрыта тестами |
| 6 | `vn-store`: проект, атомарная запись, копии, `.vnpak`, экспорт, сохранения игрока | Надёжность файлов и выпуск игр |
| 7 | Веб-плеер на JS + трасса соответствия с Rust | Телефон без wasm; трасса не даёт двум движкам разойтись |
| 8 | Проверка веб-плеера в Chrome с экраном телефона | Убедиться, что на телефоне история проходится касаниями |
| 9 | `vn-view` и `vn-player`: игра на egui, звук, меню, слоты | Предпросмотр и игра — один код |

| 11 | Редактор: чистые части (отмена, ИИ-запросы, обновление, сервер, правки истории) с тестами | Интерфейс остаётся тонким |
| 12 | Редактор: окно, панели, вкладки, диалоги | Основная работа автора |
| 13 | Запуск под xvfb со снимками; найдены и исправлены: значки вне шрифта, выравнивание списков, широкая панель графа, рывок спрайта в кадре начала перетаскивания, герой без одежды на сцене | Проверка глазами, а не только тестами |
| 14 | Сценарии через интерфейс (egui_kittest): проект, событие, отмена, сохранение, проверка, сборка, обновление, ИИ, автосохранение, горячие клавиши | Поведение закреплено тестами |
| 15 | В настоящем окне мышью: перетаскивание персонажа, соединение сцен, сохранение, сборка игры | Сквозная проверка с результатом на диске |
| 16 | CI и выпуск на GitHub Actions | Сборка Windows и источник для кнопки обновления |
| 17 | Документация: README, архитектура, словарь, журналы | Требование ТЗ |

## Чего не сделано из принципов и почему

- Инструменты `crapper`, `dryer`, `mutator` в среде отсутствуют; сложность и дублирование проверялись
  `cargo clippy` и чтением. Мутационного тестирования не было.
- «Красная» фаза TDD (тест падает до кода) соблюдалась не везде: сценарии интерфейса писались после кода окна.
- Проверка доступности (имена полей для экранных дикторов) в тестах интерфейса отключена:
  у части полей ввода нет подписей для вспомогательных технологий.
